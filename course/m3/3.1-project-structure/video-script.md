# 3.1 录播参考脚本：项目文件夹的标准结构

> 建议时长：7–9 分钟（边对比「大杂烩文件夹」和仓库里真实的 `practice/` 目录树边讲，以下为口播要点与屏幕节点，不作逐字稿）。

## 中英术语读法

| 术语 | 读法 | 首次出现时的口头解释 |
|---|---|---|
| `README.md` | 瑞德米 | 项目总说明书，写清干嘛用、怎么跑 |
| `requirements.txt` | 瑞快尔门茨点 T-X-T | 本项目用到的 Python 第三方库清单 |
| `config.yaml` | 康菲格点牙默 | 给人随时改参数的配置文件 |
| `.env` / `.env.example` | 点 E-N-V / 模板 | 装真实 API 密钥的本地文件 / 可以公开的空模板 |
| `scripts/` / `src/` | 斯奎普茨 / 源码目录 | 存放正式可复用脚本的文件夹 |
| `data/` / `output/` | 原料仓 / 成品库 | 只读原始数据目录 / 加工结果输出目录 |

---

## 0:00 – 0:50｜开场 Hook（戳中「终版_真终版」痛点）

- **屏幕画面**：左屏摆一个乱糟糟的「大杂烩文件夹」（`test.py`、`test_fix_v2.py`、`模型比价_终版_真终版.xlsx`、`key.txt`），右屏摆规整的 `ai-radar` 5 分区目录树。
- **口播要点**：
  - 「用 AI 写脚本两周后，90% 的人文件夹都长左边这样：自己分不清跑哪个、AI 扫目录也容易改错旧文件、打包发人还会顺手把密钥发出去。」
  - 引出 M3 模块：从「读懂单个脚本」升级到「看懂一整座规范的工程工地」。

## 0:50 – 3:30｜5 大分区铁律（用工地分区一秒记牢）

- **屏幕画面**：在 `ai-radar/` 目录树上逐个高亮 5 块区域——门厅（`README`/`config`/`requirements`/`.env.example`/`.gitignore`）、原料仓 `data/`、加工厂 `scripts/`、成品库 `output/`、隔离区 `.venv/`。
- **口播要点**：
  - **重点破误解**：「别觉得只有大厂程序员才需要分目录。当你用 AI 干活时，目录越规范，AI 越不容易犯错——它扫一眼目录就知道原件在 `data/`、脚本放 `scripts/`、成品吐进 `output/`。」
  - 强调两条底线：`data/` 只读不改；`.env`、`.venv/` 和 `output/` 进 `.gitignore`。

## 3:30 – 5:45｜现场逛一遍升级后的 `practice/` 目录

- **屏幕画面**：在编辑器左侧文件树里逐个点开 `practice/README.md`、`practice/config.yaml`、`practice/requirements.txt`、`practice/.env.example` 和 `practice/scripts/` 里的 3 个脚本。
- **口播要点**：
  - 交代 `practice/README.md` 最该写清的 3 块：目录导航、复制即用命令、安全约定。
  - 给观众一句可直接抄的提示词：以后开新项目，第一句就让 AI 按这套标准骨架建目录。

## 5:45 – 7:30｜30 秒结构诊断练习 + 下集预告

- **屏幕画面**：贴出第 5 节同事的 `weekly-report/` 目录，停 5 秒让观众挑出 4 个毛病（尤其标红 `.gitignore` 漏掉 `.env` 和 `.venv/` 的高危隐患）。
- **口播要点**：
  - 预告 **3.2《"在我电脑上能跑"：依赖与环境》**：目录规整好了，怎么保证发给同事或换一台电脑 1 分钟就能原样跑通？下节课讲透 `requirements.txt` 和 `.venv`。
