# 3.4 录播参考脚本：密钥与数据安全

> 建议时长：9–11 分钟（边看 `.env.example`、`.gitignore`、DSH 设置开关与 GitHub Push Protection 文档边讲，以下为口播要点与屏幕节点，不作逐字稿）。

## 中英术语读法

| 术语 | 读法 | 首次出现时的口头解释 |
|---|---|---|
| API Key | A-P-I Key（密钥） | 调用云端大模型或接口的「免密银行副卡」 |
| `.env` / `.env.example` | 点 E-N-V / 模板 | 存真实密钥的本地文件 / 可以提交的空占位模板 |
| Revoke / Rotate | 吊销 / 轮换 | 让泄露的旧密钥立刻作废并换发一把新的 |
| Push protection | 推送保护 | GitHub 在你把密钥推上仓库前自动拦截的安全闸 |
| Session Log | 会话日志 | 你和 AI 的对话与操作记录 |
| Anonymize | 中文直接说「脱敏」 | 把真实姓名、手机号替换成假编号或删掉 |

## 0:00 – 0:50｜开场 Hook（两起最让人出冷汗的事故）

- **屏幕画面**：大字左右对比两件事——左边「Key 误传公开 GitHub，3 分钟被爬虫刷爆账单」，右边「把带员工工资/客户手机号的原表直接拖进公有云 AI」。
- **口播要点**：
  - 「代码算错顶多返工重跑；密钥泄露和敏感数据裸奔，是真的会赔钱甚至惹官司的。M3 压轴课不讲晦涩加密算法，只给你两张拿来就能防翻车的底线清单。」

## 0:50 – 4:15｜上半场：API Key 防泄四铁律 + 泄露急救步

- **屏幕画面**：依次展示 `practice/.env.example`、`.gitignore` 里的 `.env` 拦截规则，再切到 GitHub 官方 `Push protection` 文档页。
- **口播要点**：
  - 把 API Key 比作「不记名免密银行副卡」，讲清 4 条铁律：
    1. `.env` 留本地进 `.gitignore`，仓库里只交 `.env.example` 空模板；
    2. 申请完 Key 第一时间去后台设消费上限（比如先设 20 美元上限锁死风险）；
    3. **关键破误解**：泄露推上 GitHub 后，**删掉代码重新 push 根本没用！** Git 会保留旧提交，爬虫几十秒就抄走了——**第一动作永远是立刻去服务商后台点吊销（Revoke）**；
    4. 介绍 GitHub `Push protection` 是最后一道安全气囊，但不能替代日常规范。

## 4:15 – 7:30｜下半场：职场数据「红黄绿三灯清单」+ 本地先脱敏绝招

- **屏幕画面**：亮出绿灯 / 黄灯 / 红灯三档数据清单，接着打开 DeepSeek Harness「设置 → 通用设置」滚到最底，圈出默认打开的 **「在使用官方模型 API 时上传 Session Log」** 开关，现场演示把它关掉！
- **口播要点**：
  - 逐档点名典型文件：公开快照（绿灯）、内部非敏感汇总（黄灯——隔离工作区 + 关 Session Log）、身份证/手机号/工资条/保密合同（红灯——绝不裸奔喂公有云 AI）。
  - **高光实用技巧（放慢语速讲）**：「手里真有 3,000 行真实客户表要分析怎么办？只把表头 + 2 行假样例发给 AI，让它写好 `anonymize.py` 和分析脚本，你自己在终端本地跑——Python 全程在你自己硬盘上算，3,000 个客户手机号一个字都不出电脑！」

## 7:30 – 9:30｜3 个险情快问快答 + M3 结业与下集预告

- **屏幕画面**：贴出第 5 节 3 个突发场景（误推 Key 怎么办 / 工资表怎么核对 / 打包发同事剔除哪两样），留 5 秒给观众作答再揭晓。
- **口播要点**：
  - 祝贺 M3 全部 4 课通关：目录结构、依赖环境、三件套配置和安全底线全部齐活。
  - 预告 **M4 Git 与 GitHub**：下一课 **4.1《Git = 游戏存档》**，正式上手给每一次改动留存档、出错一键回退。
