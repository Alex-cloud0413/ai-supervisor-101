# 0.1 录播参考脚本：AI 不是在聊天，是在「干活」

> 建议时长：8–10 分钟（边操作边讲，以下为口播要点与屏幕节点，不作逐字稿）。

## 中英术语读法

| 术语 | 读法 | 首次出现时的口头解释 |
|---|---|---|
| Agent | 诶真特（或直接读英文 Agent） | 能自己调用工具干活的 AI 助手 |
| Harness | 哈尼斯 | 给模型套上的执行外壳，负责在你电脑上读写文件、跑命令 |
| DeepSeek Harness / DSH | D-S-H | 这套课的主演示工具 |
| OpenRouter | 欧朋劳特 | 聚合了全球几百家大模型的公开模型目录和接口平台 |
| Token | 托肯 | 大模型按字词切分计费的最小单位，通常按「每百万 Token 多少钱」报价 |
| Trajectory | 中文界面直接说「轨迹」 | AI 后台每一步的流水账 |
| Diff | 迪夫 | 文件修改前后的对比，绿的是新增、红的是删掉 |
| `bash` | 巴什 | 命令行工具，用来敲系统指令 |
| `.py` | 点 P-Y | Python 脚本文件的后缀 |

## 0:00 – 0:45｜开场 Hook（先抛翻车反差，交代本课只看不装）

- **屏幕画面**：先停在刚跑完的第 1 轮结果页和 `output/模型比价Top10.xlsx`，圈出「AI 汇报已完成」和「商用榜第 1 名居然是 `:batch` 离线版、全量榜第 7 名居然是音乐生成模型 `lyria-3`」的反差。
- **口播要点**：
  - 直接抛真实案例：「我刚拉了 OpenRouter 公开的 470 个真实大模型报价，让 AI 帮我挑出最便宜、能看图的前 10 个模型做成 Excel。AI 一会儿就说做完了，表还分了三个 Sheet，看着特别专业。结果我打开一核对：商用第 1 名是不能实时聊天的离线批处理版，全量第 7 名甚至是谷歌的音乐生成模型。」
  - **先给观众吃定心丸**：明确说一句「今天这节课只看不装，什么软件都不用下、什么命令都不用敲，先看懂 AI 怎么干活、怎么验收。安装留到 1.4 课手把手带你走。」
  - 引出主线项目 `ai-radar`（AI 选型与每日情报雷达）：这套课不用过时的虚构教材表格，而是带着大家从零盯住 AI，搭一套你自己平时真能用上的工具。

## 0:45 – 2:30｜拆清楚：Agent = 模型 + Harness

- **屏幕画面**：切到极简示意图（或在白板现场画三块：`你` ↔ `Harness（DSH）` ↔ `模型（Gemini / DeepSeek）`）。
- **口播要点**：
  - 讲清分工：模型只在云端动脑子，碰不到你的硬盘；Harness 装在你电脑上，替模型长手长脚，负责读文件、写脚本、跑命令、弹审批框。
  - **顺手破一个常见误解**（停顿一下强调）：很多人看到 DeepSeek Harness 的名字，以为只能用 DeepSeek 模型。演示点击右下角模型选择器，给观众看本课用的就是 `Gemini 3.8 Flash`。
  - 强调安全归属：电脑安不安全，靠的是 Harness 的权限闸门和你自己的审批，不是指望模型「自觉」。

## 2:30 – 5:30｜现场操作：发任务 + 切到「轨迹」看 26 步

- **屏幕画面**：打开 DSH 网页版，选中 `ai-radar` 工作区，发送筛选 OpenRouter 多模态模型 Top 10 的指令。完成后（录播可快进等待）点顶部「轨迹」。
- **口播要点**：
  - 指出底部 `1 轮 26 步`、`584K tok`：你只发了一句话，后台模型和 Harness 来回配合了 26 步。
  - 带着观众看「读 → 改 → 跑 → 看 → 再改」循环：
    - 指着顶部彩色块：橙色是正常工具，红色是报错；
    - 指着 `fatal: not a git repository` 那行红错：它想用 `git` 确认原始数据没被改，报错后马上换普通查看命令复核——这就是会自己纠错的循环。
  - **关键停顿**：指着轨迹里 `google/lyria-3-pro-preview {'prompt': '0', 'completion': '0'}` 那一行——点出翻车原因：它明明亲眼看过 `lyria-3`，却只盯价格为 `0`、忘了查输出模态是不是文字，结果把音乐模型塞进了榜单。

## 5:30 – 7:45｜现场修口径 + 扫一眼 Diff

- **屏幕画面**：切回「对话」，发第 2 轮明确反馈（排除 `:batch` 和 `~` 别名、按 `output_modalities` 过滤非文字模型、写成正式脚本 `build_top10.py`、按综合均价排）。完成后点开 `已编辑 build_top10.py`，展开右侧「第 2 轮改动」并滚到第 38–70 行。
- **口播要点**：
  - 2 分钟修完，累计 `2 轮 37 步`，榜单立刻清爽，Top 1 变成 `google/gemma-3-4b-it`（综合均价 `¥0.324/M`），前 5 名全是能直接商用实时调用的多模态对话模型。
  - 鼠标依次指着右边 4 段绿字 `if`：`startswith("~")`、`":free" in m_id or ":batch" in m_id`、`outputs != ["text"]`、`p_usd_raw <= 0 or c_usd_raw <= 0`。
  - 告诉观众：你今天一行 Python 都没学，但扫一眼这几行绿字，已经能确认 AI 真的把 4 道筛子写进代码里了，不是口头敷衍你。

## 7:45 – 9:00｜收尾与下集预告

- **屏幕画面**：回到 5 步流程图，在「你」的位置画一个框。
- **口播要点**：
  - 一句话收尾（不升华）：能跑通不等于口径对；当监工的第一步，是养成点开「轨迹」、扫一眼 Diff 关键条件、核对前几行结果的习惯。

## 录制注意事项

- 录屏前确认浏览器只打开 `ai-radar` 工作区，不暴露个人目录、邮箱或 API Key。
- 模型输出带有一定随机性：如果实录时 `Gemini 3.8 Flash` 第 1 轮自己排除了 `:batch` 但漏掉了 `lyria-3` 或 `~` 别名（或反之），直接按实录中真实出现的口径漏洞现场演示即可，绝不伪造翻车。
