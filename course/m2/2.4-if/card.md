## 第 2 张：真实教训——条件写宽一毫米，音乐模型就混进来了

**页眉标签**：01｜真实漏洞

Google 音乐模型 `lyria-3` 的真实输出字段长这样：
`"output_modalities": ["text", "audio"]`

- AI 写 `if "text" not in outputs:` → 里面含 `"text"`，**直接放行**！
- 改成 `if outputs != ["text"]:` → 必须严格纯文字输出，**一次性拦下 17 个非纯文本模型**！

业务口径 90% 的坑，就藏在 `if` 后面这一行条件里。

## 第 3 张：6 个必须眼熟的判断符号

**页眉标签**：02｜符号速查

- `==`：等于（**两个等号**才是判断，单个 `=` 是赋值！）
- `!=`：不等于（如 `outputs != ["text"]`）
- `>` / `>=` / `<` / `<=`：比大小（如 `prompt_usd <= 0`）
- `in` / `not in`：是否包含（如 `":batch" in model_id`）
- `.startswith("~")`：是否以 `~` 开头

别忘了 Python 靠**左侧 4 个空格缩进**决定哪些行归这个 `if` 管。

---

## 第 4 张：头号翻车点——把 `or` 写成了 `and`

**页眉标签**：03｜逻辑陷阱

要把输入价或输出价不合规（`<= 0`）的模型踢掉：

- ✅ `if prompt_usd <= 0 or completion_usd <= 0:` → **任意一边 `<= 0` 就踢**。
- ❌ `if prompt_usd <= 0 and completion_usd <= 0:` → 两边**同时** `<= 0` 才踢，结果单边标价 `0` 的异常模型直接漏网！

---

## 第 5 张：验收 AI 过滤条件的「三查口诀」

**页眉标签**：04｜监工查错

以后在 Diff 里看到 AI 改了 `if`，花 5 秒核对 3 件事：

1. **查方向**：想留下 `>= 128000`，那拦掉（`return False`）的就得是 `< 128000`，别写反！
2. **查边界**：含不含等于号（`<` 还是 `<=`）？
3. **查连接词**：心里把 `and` 默念成「并且」、把 `or` 默念成「或者」，看通不通。

## 正文配文（小红书发布参考）

查 0.1 课那个翻车（音乐生成模型混进文字对话 Top 10）时，翻开真实 JSON 发现一个超经典的细节：`lyria-3` 的输出模态居然写着 `["text", "audio"]`！

如果 AI 只写了 `if "text" not in outputs`，照样放行；必须写成 `outputs != ["text"]` 才拦得住。还有把淘汰条件里的 `or` 错写成 `and`，一跑就会放进单边标价 0 的异常模型。
