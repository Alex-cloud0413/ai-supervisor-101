# 4.3 小红书速查卡：分支与合并

> 排版适配：3:4 竖版，每张 1 个独立语义点，当前仅交付纯文字文案。

---

## 封面卡（第 1 张）

- **主标题**：让 AI 放手大改不怕崩：零基础看懂 Git 分支与合并
- **副标题 / 导语**：主线 `main` 稳如老狗，实验分支随便折腾；遇到合并冲突一招 `abort` 安全逃生

---

## 内容卡 01

- **页眉标签**：01｜什么是分支？给 AI 开一条「隔离试错跑道」
- **正文**：
  - **`main` 分支**：正式稳定版，只放验收通过的代码
  - **实验分支（`feat/`、`exp/`、`agent/`）**：平行 2 号存档槽
  - 试成了 → 合并回 `main`；试崩了 → 切回 `main` 一键扔掉
  - 破误解：建分支**不复制大文件**，只是 41 字节书签，零成本放心开！

---

## 内容卡 02

- **页眉标签**：02｜日常 5 条命令走天下
- **正文**：
  - `git branch`：看当前在哪个分支（带 `*` 号的）
  - `git switch -c feat/新功能`：新建并切到实验分支（旧写法 `git checkout -b`）
  - `git switch main`：切回稳定主线
  - `git merge feat/新功能`：站在 `main` 上把成果并回来
  - `git branch -d feat/新功能`：合完清理临时分支

---

## 内容卡 03

- **页眉标签**：03｜撞上「合并冲突」别慌！3 条线看懂它
- **正文**：
  - 什么时候会冲突？**两个分支同时改了同一个文件的同一行**
  - 文件里会出现 3 条提示线：
    - `<<<<<<< HEAD` 下方 = 当前分支（`main`）的写法
    - `=======` = 中间分隔线
    - `>>>>>>> 分支名` 上方 = 要并进来的写法
  - 记住：选好要留的那行后，**必须把这 3 条标记线彻底删干净**！

---

## 内容卡 04

- **页眉标签**：04｜冲突时的万能逃生键
- **正文**：
  - 看到 `CONFLICT` 一时拿不准怎么选？
  - 立刻敲一行：
    `git merge --abort`
  - 1 秒干干净净退回合并前的状态，什么都不会丢！

---

## 正文配文（小红书发布参考）

很多职场朋友用 AI 改项目时最纠结：原来的工具明明跑得好好的，想让 AI 试着加个大功能，又怕折腾到一半把能用的版本改崩了。

解决办法就是 Git 的「分支（Branch）」：
开工前让 AI 先 `git switch -c feat/xxx` 开条隔离跑道，主线 `main` 一根头发都不动；验收通过再 `git merge` 合回来，试崩了直接切回 `main` 扔掉！
万一撞上合并冲突，记住万能逃生键 `git merge --abort`，随时全身而退。
