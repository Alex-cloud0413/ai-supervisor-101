# 4.3 录播参考脚本：分支与合并

> 建议时长：9–11 分钟（边操作边录，此脚本只作参考，不逐字照念）
> 演示材料：沿用 4.1–4.2 的 `ai-radar` Git 沙盒目录，准备一个 `config.yaml` 汇率改 `7.25` vs `7.3` 的冲突现场。

---

## 中英术语读法

| 术语 | 读法 | 首次出现时的口头解释 |
|---|---|---|
| `branch` | 布兰奇 | 分支，相当于游戏里的「平行 2 号存档槽」 |
| `main` | 梅恩 | 默认主线分支，专门放稳定能跑的正式版本 |
| `switch` | 斯威奇 | 切换分支的新命令（老写法叫 `checkout`） |
| `merge` | 默吉 | 合并，把实验分支验收通过的成果并回主线 |
| `conflict` | 康弗利克特 | 合并冲突，两边改了同一行，Git 停下来请你二选一 |
| `abort` | 额波特 | 中止并撤回，`git merge --abort` 是冲突时的万能逃生键 |

## 分段参考

| 时间 | 屏幕画面 | 口播要点 |
|---|---|---|
| 00:00–01:15 | 展示主线/分支双轨流程图 | 抛出场景：已经稳稳在跑的 `ai-radar` 想让 AI 试一个大改版，直接改主版本风险太大——用游戏「另存 2 号存档槽」引出分支。 |
| 01:15–03:10 | 终端依次展示 `git branch`、`git switch -c feat/strict-hn`、顺口对照老命令 `git checkout -b` | 讲清 5 条分支命令与命名习惯（`feat/`、`fix/`、`exp/`、`agent/`）；**破误解**：建分支不是把几十兆文件复制一遍，只是 41 字节书签指针，零负担放心开。 |
| 03:10–05:10 | 在 `feat/strict-hn` 改 `min_points: 500` → commit → `git switch main` → `git merge feat/strict-hn` | 演示顺滑的 `Fast-forward` 合并，顺带强调顺序：**站在谁上面，就把别人合进谁里面**（先切 `main` 再 `merge`）。 |
| 05:10–07:40 | 故意制造 `main`（`7.25`）与 `exp/rate-73`（`7.3`）同改一行 → 触发真实 `CONFLICT` → 打开 `config.yaml` 圈出 3 条标记线 | **化解恐惧核心段**：冲突一点不可怕！把 `<<<<<<< HEAD`、`=======`、`>>>>>>> exp/rate-73` 一句一句翻译给人听，接着演示一键逃生命令 `git merge --abort` 瞬间恢复干净。 |
| 07:40–09:00 | 切到第 5 节 3 个场景拍板练习 | 停顿 5 秒，重点敲黑板：解决冲突后必须把 `<<< / === / >>>` 标记删干净，否则 YAML / Python 直接报语法错。 |
| 09:00–09:40 | 预告下一课 4.4《从 0 认识 GitHub：注册与全平台板块导览》 | 本地 Git 三件套（4.1–4.3）正式通关，下一课零基础登顶云端 GitHub！ |

## 录制注意事项

- 录制冲突演示时，刻意放慢切回 `config.yaml` 展示 `<<<<<<< HEAD` 到 `>>>>>>>` 这 5 行的节奏，让观众看清结构，消除「看到红字报错就心慌」的本能反应。
- 强调 `-d`（安全删已合并分支）与 `-D`（强制删除）的区别，呼应 1.3 课「看清大小写参数再批准」的监工习惯。
