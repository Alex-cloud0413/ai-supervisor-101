# 4.2 录播参考脚本：读懂 diff

> 建议时长：8–10 分钟（边操作边录，此脚本只作参考，不逐字照念）
> 演示材料：沿用 4.1 课的 `ai-radar` Git 沙盒目录，确保终端开启 Git 彩色高亮（红删绿增清晰可见）。

---

## 中英术语读法

| 术语 | 读法 | 首次出现时的口头解释 |
|---|---|---|
| `diff` | 迪夫 | difference 的缩写，只把改前改后的差异行拎出来给你看 |
| `stat` | 斯塔特 | statistics 统计摘要，列出改了哪几个文件、各增删几行 |
| `staged` | 斯泰吉德 | 已经放进待打包箱（暂存区）、准备要 commit 的改动 |
| `hunk` | 汉克 | diff 里每个 `@@ ... @@` 开头的一小块相邻改动 |

## 分段参考

| 时间 | 屏幕画面 | 口播要点 |
|---|---|---|
| 00:00–01:10 | 打开 156 行的 `daily_briefing.py` 快速滚一遍 | 抛出痛点：AI 一句「改好了」，难道要从头重读 200 行代码？监工验收靠的不是通读全文，而是只看变化的 `diff`。 |
| 01:10–03:20 | 展示 `config.yaml` 的彩色 `git diff` 输出，用鼠标依次圈出 4 块区域 | 逐一拆解：① `--- a/` / `+++ b/` 查文件名防越界；② `@@ -9,7 +9,7 @@` 认行号块；③ 红 `-` 绿 `+` 是「改一行 = 删旧行 + 加新行」；④ 白色上下文行。顺带提醒按 `q` 退出长 diff 翻页。 |
| 03:20–04:30 | 对比演示 `git diff --stat`、`git diff`、`git diff --staged` | 强调监工两步走：**先 `--stat` 看大盘防越界，再 `git diff` 看红绿行验口径**。破误解：红 `-` 多不等于坏事，但只让改 1 行却蹦出 120 行增删才是大警报。 |
| 04:30–07:00 | 切到 `daily_briefing.py` 的真实 `git diff`（`<` 变 `<=`，`reverse=True` 变 `False`） | **核心高潮**：带着观众用 15 秒揪出 2 个隐藏暗坑——连上 2.4 课的 `if` 条件，说明为什么哪怕只改了 2 行也必须盯着看语义，最后顺手用 `git restore` 一键打回。 |
| 07:00–08:20 | 展示第 5 节的「只让改汇率到 7.3」双坑练习 | 停顿 5 秒，点破两大典型 AI 偷改：动了只读 `data/` 快照 + 顺手删了 `":free"` 排除规则。 |
| 08:20–09:00 | 预告下一课 4.3《分支与合并》 | 小改用 `diff` 验收，遇到大改版想让 AI 放手试错又不污染主线怎么办？下节开「平行实验分支」。 |

## 录制注意事项

- 录制前确认终端运行 `git config color.ui auto` 已生效，确保 `-` 行显示红色、`+` 行显示绿色，视觉对比最直观。
- 如果 `git diff` 内容短没有进入翻页模式，可以顺口演示或口头提示「改动超过一屏时按小写 `q` 退出」，避免新手卡在 `:` 提示符里不知所措。
