# 4.5 录播参考脚本：GitHub 仓库页导览（以 DeepSeek Harness 仓库为例）

> 建议时长：10–12 分钟（浏览器边点边讲，以下为口播要点与屏幕节点，不作逐字稿）。

## 中英术语读法

| 术语 | 读法 | 首次出现时的口头解释 |
|---|---|---|
| GitHub | 吉特哈布（Git-Hub） | 托管 Git 项目的在线网站 |
| Repository / Repo | 瑞坡（Repo） | 一个项目的独立「仓库」 |
| Star | 斯塔（收藏/星星） | 收藏兼点赞 |
| Fork | 福克（叉子/复刻） | 复制一份仓库到你自己的 GitHub 账号下 |
| Issue | 一休（问题单） | 报 Bug、提需求的工单区 |
| Pull request / PR | P-R | 合并请求：提交代码改动、等审核通过再合并 |
| Discussions | 社区讨论区 | 像论坛一样的公告、问答和反馈区 |
| Actions | 自动化流水线 | 每次改代码自动跑测试的机器人记录 |
| Releases | 正式发布版 | 打包好的版本号、更新日志和安装包 |
| `README.md` | 瑞德米（Read Me） | 项目说明书 |
| `LICENSE` | 莱森斯（许可证） | 规定能不能免费商用、要遵守什么条件 |
| `.gitignore` | 点 git-ignore | 不上传清单，防密钥和缓存传到网上 |
| `AGENTS.md` | 诶真特思点 M-D | 给 AI 看的仓库规则书 |

---

## 0:00 – 0:45｜开场 Hook（从老板转发的链接切入）

- **屏幕画面**：浏览器直接打开 `https://github.com/deepseek-ai/deepseek-harness` 首页，鼠标在满屏英文按钮上扫一圈。
- **口播要点**：
  - 直接抛场景：「上一课咱们刚注册完 GitHub、把整个平台的广场和工作台摸清了。这节课进入实战——老板或同事甩来一个具体仓库链接，问你这个 AI 工具能不能用、最新是哪个版本、公司用有没有版权问题，点开满屏英文到底先点哪？」
  - 一句话定调：今天不用看一行源码，10 分钟带你把单个 GitHub 仓库页的每个区域摸透。以后打开任何开源工具，1 分钟查完所有关键信息。

## 0:45 – 1:45｜衔接 4.4：从平台大厅走进单个仓库

- **屏幕画面**：简单画两框（本地电脑 Git ↔ 云端 GitHub 单个仓库内部）。
- **口播要点**：
  - 承接 4.1–4.4：4.4 认识了平台全局板块，这一课专门拆解具体某一个仓库页。
  - 顺口破误解：公开仓库不等于随便商用，必须看 `LICENSE`。

## 1:45 – 3:30｜顶栏与右上角 3 个按钮（重点防点错 Fork）

- **屏幕画面**：聚焦 DSH 首页顶栏 `deepseek-ai / deepseek-harness`、`Public`、以及右上角 `Notifications`、`Fork 35.3k`、`Star 284k`。
- **口播要点**：
  - 先看斜杠前后的「谁发的 / 叫什么」；再看 `Public`。
  - 重点停顿讲 **`Fork`**：新手最爱点 `Fork` 以为是下载，其实那是复制到你自己的云端账号；真正下载源码要点下面绿色的 `<> Code`，下载安装包要去右侧 `Releases`。

## 3:30 – 6:15｜顶部功能标签栏（两个真实仓库对照）

- **屏幕画面 1**：停在 DSH 顶栏（`Code` / `Discussions` / `Security and quality` / `Insights`），顺手点开 `Discussions` 展示里面的 `[Bug]` 帖子。
  - **口播要点**：故意指出「咦，怎么没有常见的 `Issues` 和 `Pull requests`？」解释仓库管理员可以按需开关标签——DSH 把报 Bug 和问答统一放进了 `Discussions`。
- **屏幕画面 2**：切到 `openai/codex` 浏览器标签页，依次点开 `Issues`（指彩色 `bug` / `windows-os` 标签）、`Pull requests`（指 `Approved` 和 `35/35` 检查）、`Actions`（指绿勾和红叉）。
  - **口播要点**：一句话一个标签讲清用途——遇到报错先搜 `Issues`（或 `Discussions`），看改动审核看 `PR`，看自动质检看 `Actions`。

## 6:15 – 8:45｜Code 主页 + Releases + 必认的 4 个根目录文件

- **屏幕画面**：切回 DSH 首页，依次点：
  1. 右侧 `Releases` → 指着 `v0.2.2-rc.5` 和黄色 `Pre-release` 标，解释预览版含义，展开 `Assets`；
  2. 首页往下滚看 `README` → 指着 `npx @deepseek-ai/dsh web` 安装命令；
  3. 点开 `LICENSE` → 重点放大顶部的 GitHub 摘要卡片（`Commercial use ✓`、`Liability ✗`、`Warranty ✗`）；
  4. 左侧文件树指一下 `.gitignore`，再点开 `AGENTS.md`。
- **口播要点**：
  - 讲到 `AGENTS.md` 时稍微放慢语速，埋一个钩子：「以前仓库只写给人看的 `README.md`，现在厉害的项目都会多放一份 `AGENTS.md`，专门写给 AI 看。后面 M5 我们自己也会给 `ai-radar` 写一份。」

## 8:45 – 10:00｜1 分钟实战复盘 + 下集预告

- **屏幕画面**：回到 DSH 首页，用鼠标飞快点过 4 个位置，回答开场老板或同事问的 4 个问题。
- **口播要点**：
  - 总结：以后打开任何开源仓库，记住固定动线——**顶栏认身份 → README 看怎么用 → LICENSE 看能不能商用 → Releases 看最新版本 → Issues/Discussions 搜报错**。
  - 预告 4.6：认完按钮后，下节课教你一套 3 分钟体检法，一眼分辨一个开源项目到底是真活跃还是已经烂尾的空壳。

## 录制注意事项

- 录屏时建议用未登录的隐身窗口，避免露出自己的 GitHub 头像、私有仓库通知或个人邮箱。
- 实际录制当天页面上的 Star 数、Commit 数和最新 Release 版本号会比课件截图更新，直接按屏幕当前真实数字口播即可。
