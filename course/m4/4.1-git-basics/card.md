## 内容卡 01

- **页眉标签**：01｜先分清：Git ≠ GitHub
- **正文**：
  - **Git**：装在你自己电脑上的本地存档软件，断网也能用
  - **GitHub**：存 Git 存档的云端平台（像代码世界的网盘 + 广场）
  - **监工铁律**：让 AI 做任何大改动之前，先确认本地已经打好存档！

---

## 内容卡 02

- **页眉标签**：02｜日常只需记住这 5 个动作
- **正文**：
  - `git init -b main`：给新项目放一台存档机（只做一次）
  - `git status -s`：检查桌面乱不乱（`M` 改过、`??` 新文件）
  - `git add .`：把验收通过的改动放进待打包箱
  - `git commit -m "说明"`：正式封箱按下保存进度
  - `git log --oneline`：一行一条看全部历史存档

---

## 内容卡 03

- **页眉标签**：03｜AI 改坏了？2 招安全读档
- **正文**：
  - **还没 `commit`（刚改坏草稿）**：
    `git restore <文件名>` → 3 秒退回上一档原样
  - **已经 `commit`（事后才发现错）**：
    `git revert HEAD` → 新增一笔反向抵消记录，留痕不删史
  - **高危红线**：见到 `git reset --hard` 立刻拦下，未存档改动会直接蒸发！

---

## 内容卡 04

- **页眉标签**：04｜最容易踩的 1 个误解
- **正文**：
  - 误以为：装了 Git 就会自动实时备份
  - 真相：Git **只保护你亲手 `commit` 过的那一刻**
  - 好习惯：小步高频打存档——每跑通一个小功能就 `commit` 一次，写一句人话备注

## 正文配文（小红书发布参考）

让 AI 帮改代码最怕什么？改到第 3 轮越改越乱，想退回一小时前却发现 `Ctrl + Z` 早就撤不回去了。

其实你根本不用学复杂 Git 命令，把它当成「打 Boss 前的游戏存档机」就行：
开工前 `git status` 看一眼，验收完 `git add .` + `git commit` 存一档；
没存档改坏了用 `git restore`，已存档反悔用 `git revert`——全程安全留痕，绝不碰 `git reset --hard`！
