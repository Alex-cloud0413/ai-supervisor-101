# 4.6 录播参考脚本：怎么判断一个开源项目靠不靠谱

> 建议时长：9–11 分钟（边操作边录，此脚本只作参考，不逐字照念）
> 演示材料：浏览器预先打开 `github.com/atom/atom`、`github.com/openai/codex`、`github.com/n8n-io/n8n` 与 `choosealicense.com/licenses/` 四个公开标签页（无需登录）。

---

## 中英术语读法

| 术语 | 读法 | 首次出现时的口头解释 |
|---|---|---|
| `Archive` / `Archived` | 阿凯夫 / 阿凯夫德 | 归档只读，说明作者已经宣布停更不再维护 |
| `License` | 莱森斯 | 开源协议，规定这份代码能不能改、能不能商用 |
| `MIT` / `Apache` | 艾姆艾踢 / 阿帕奇 | 最常见的宽松开源协议，允许商用只需留署名声明 |
| `GPL` / `AGPL` | 鸡皮艾欧 / 诶鸡皮艾欧 | 传染性开源协议，二次分发或联网提供服务须把改动一并开源 |
| `SaaS` | 萨斯 | 把软件部署在云端按月订阅卖给外部客户的模式 |

## 录制注意事项

- 打开 `choosealicense.com/licenses/` 时，用鼠标清晰指出 `Permissions`（绿勾）、`Conditions`（蓝圈 `Network use is distribution`）和 `Limitations`（红叉）三列，视觉记忆极强。
- 讲解开源协议时保持客观口头提示：「这是职场初筛常识，真要贴牌做商业软件卖钱，务必交给法务把关。」
