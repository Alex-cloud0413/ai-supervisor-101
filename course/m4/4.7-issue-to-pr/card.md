# 4.7 小红书速查卡：Issue → PR → 审核 → 合并

> 排版适配：3:4 竖版，每张 1 个独立语义点，当前仅交付纯文字文案。

---

## 封面卡（第 1 张）

- **主标题**：看懂 GitHub 协作闭环：Issue → PR → 审核 → 合并
- **副标题 / 导语**：告别微信群互传压缩包！给 AI 当监工最高效的姿势，都在这 4 个标签页里

---

## 内容卡 01

- **页眉标签**：01｜4 个高频英文词，一句话全听懂
- **正文**：
  - **Issue（工单）**：「这里有 Bug / 我想要个新功能」的需求单
  - **PR（Pull Request）**：「我在实验分支干完活了，申请合回 `main`」的交卷单
  - **Review（审核）**：监工看红绿差异、留批注，选批准或打回
  - **Merge（合并）**：审核过关正式上线，并自动把原 Issue 关单！

---

## 内容卡 02

- **页眉标签**：02｜审一份 PR，只看顶部的 4 个标签页
- **正文**：
  - **① `Conversation`**：看摘要和 `Fixes #编号`，确认没偏题
  - **② `Commits`**：看提交步骤清不清楚
  - **③ `Checks`**：看自动测试是不是全绿（有红叉先别合！）
  - **④ `Files changed`**：网页版 `git diff`，盯住改了哪几个文件、红删绿增对不对

---

## 内容卡 03

- **页眉标签**：03｜监工拍板的 3 个审核按钮
- **正文**：
  - **`Comment`（仅留言）**：先提疑问，暂不拍板
  - **`Approve`（批准通过）**：亮绿勾放行，允许合并进 `main`
  - **`Request changes`（打回修改）**：发现越界改文件、漏进 `.env` 或逻辑写反，立刻打回让 AI 重改！

---

## 内容卡 04

- **页眉标签**：04｜AI 时代的真实样板（OpenAI Codex 实景）
- **正文**：
  - 社区用户提 Issue `#31520` 报安装故障
  - AI 分支 `agent/fix-install-compact-release-json` 提交 PR `#31667`（写上 `Fixes #31520`）
  - 36 项自动检查通过 + 人工审完 2 个文件点绿勾批准
  - 合并 2 秒后原 Issue 自动关闭——全程公开留痕、只用 26 小时！

## 正文配文（小红书发布参考）

为什么专业团队和 AI Agent 协作从来不在微信群里传压缩包？
因为他们全都在用 GitHub 这条四步标准流水线：**Issue → PR → 审核 → 合并**！

哪怕你一行代码都不写，学会看懂 PR 顶部的 4 个标签页（`Conversation`、`Commits`、`Checks`、`Files changed`），就能像资深负责人一样验收 AI 交上来的作业：
检查全绿 + 文件没越界 + 红绿 diff 逻辑对，点一下 `Approve` 和 `Merge`，正文写了 `Fixes #编号` 还会自动帮你把需求单结案！
