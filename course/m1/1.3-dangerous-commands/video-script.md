# 1.3 录播参考脚本：危险命令识别表

> 建议时长：8–10 分钟（边操作边讲，以下为口播要点与屏幕节点，不作逐字稿）。

## 中英术语读法

| 术语 | 读法 | 首次出现时的口头解释 |
|---|---|---|
| `rm` | R-M（remove 的缩写） | 删除文件命令 |
| `-rf` | 杠 R-F | `-r` 连文件夹一起删，`-f` 强制不问确认 |
| `sudo` | 苏杜（sue-doo） | Mac/Linux 下向系统要最高管理员权限 |
| `curl` | 科尔（curl） | 从网址下载内容或往外发数据的命令行工具 |
| `sh` / `bash` | S-H / 巴什 | 运行脚本的命令行外壳 |
| `chmod` | C-H-mod（或读「改权限」） | 修改文件读写权限 |
| `git push --force` | git push 杠杠 force | 强行覆盖云端代码仓库的历史记录 |
| PowerShell | 帕沃谢尔 | Windows 里新版终端 |

---

## 0:00 – 0:45｜开场 Hook（先打掉「无脑点允许」的习惯）

- **屏幕画面**：直接放大展示 `rm -rf output` 的橙色「等待审批」卡片，鼠标停在「拒绝」和「允许一次」两个按钮之间。
- **口播要点**：
  - 直接点痛点：「用 AI 工具最容易出大事的动作，往往发生在权限弹窗跳出来那一秒——看都不看，顺手狂点『允许』。」
  - 一句话交代后果：在终端里删文件**不进回收站**，没有撤回键。这节课给你一张识别表和一个 4 秒核查法，以后弹什么框心里都有底。

## 0:45 – 2:00｜系统位置：三档访问模式 + 审批闸门

- **屏幕画面**：点开 DSH 输入框左下角，把「仅可查看 / 工作区内修改 / 完全权限」三档亮出来。
- **口播要点**：
  - 逐档解释：只读看报表用「仅可查看」；平时干活固定在「工作区内修改」；「完全权限」等于把钥匙全交出去，办公电脑别长期开。
  - 说明本课盯住的就是中间这道审批闸门。

## 2:00 – 5:30｜实操对比：一条该放，一条该拒

- **屏幕画面 1**：发指令让 AI 清理多余临时脚本，等 `rm inspect_sales.py ...` 弹窗出来。
  - **口播要点**：现场演示「4 秒核查法」——动词是 `rm`，没 `-rf` 没 `*`，7 个名字全是刚生成的临时 `.py`，没碰 `sales/`。点「允许一次」，看文件夹变干净。
- **屏幕画面 2**：发指令让 AI 把 `output` 整个删掉重来，等 `rm -rf output` 弹窗出来。
  - **口播要点**：扫一眼就看到 `-rf`——立刻点「拒绝」！
  - **关键停顿**（等 AI 回复完）：把屏幕停在 AI 的回复上，打破恐惧——「很多人怕点拒绝会让前面白干，你看，点完拒绝文件毫发无损，AI 自己退了一步，提出直接覆盖旧文件。拒绝不是翻车，是正常监工动作。」

## 5:30 – 8:00｜过一遍 8 类高危命令识别表（Mac + Windows）

- **屏幕画面**：切到整理好的 8 行表格（重点标红 4 个最高频：`rm -rf` / 通配符 `*` / `sudo` / `curl ... | sh`，其余 4 个快速过一遍：`git push --force`、`chmod -R 777`、越界路径 `..` / `~` / `C:\`、外发本地文件）。
- **口播要点**：
  - 不用背命令，只要眼熟「危险特征」：`-rf`、`--force`、`--hard`、`*`、`sudo`、`| sh`、`..`。
  - 顺带照顾 Windows 观众：点一下 `rd /s /q`、`Remove-Item -Recurse -Force`、`irm ... | iex` 其实就是同一回事。

## 8:00 – 9:00｜快问快答 + 下集预告

- **屏幕画面**：屏幕打出 2 条典型命令（`rm -rf sales/` vs `rm -f inspect_sales.py`），留 3 秒让观众自己判断，再揭晓答案。
- **口播要点**：
  - 收尾落地：以后看到橙色审批框，别急着点，4 秒扫完「动词 → 参数 → 路径 → 可不可逆」再下手。
  - 预告 1.4：路径、常用命令和危险命令都过关了，下节课正式把 DeepSeek Harness 装到你电脑上，配好模型，跑通第一个任务。

## 录制注意事项

- 如果本机（Mac 或 Windows）沙箱正常工作，让 AI 删工作区内的 `output` 时可能直接执行而不弹窗。录播时可以在演示前提醒，或专门用一条涉及工作区外路径的测试命令（比如往上级目录写文件）来触发真实审批弹窗；绝不演示真正删掉重要文件的操作。
