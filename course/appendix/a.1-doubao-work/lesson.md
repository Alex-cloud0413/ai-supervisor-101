# 附录 A.1 豆包工作版（不想碰终端、公司用飞书）

> 学习目标：了解字节跳动 2026 年推出的统一办公智能体「豆包工作」的定位与适用人群，看懂它与主线课程 DeepSeek Harness 的能力映射、零终端落地方式，以及在飞书办公场景里的隐私与安全边界。
>
> 演示环境：依据 2026 年 8–11 月字节跳动官方发布与权威财经报道公开信息整理（面向国内使用飞书生态、不想接触命令行终端的职场白领与中小团队；实机登录界面标注 `[可选补拍]`）。

## 1. 「我真的不想碰黑框终端，公司全员天天泡在飞书里，有国产平替吗？」

走完前面 32 节正课，你已经看懂了路径、Python、Git 和 Agent 的底层工作原理。但现实职场里有一大群非常典型的同学：
- 日常工作 80% 都在**飞书文档、飞书多维表格、飞书群和日常 Office 文件**里打转；
- 公司电脑权限管得严，不想（也没必要）折腾 Node.js、Python 虚拟环境和黑框终端；
- 希望在熟悉的中文办公软件里，直接一句话让 AI 拆任务、调工具、操作表格和浏览器把活干完。

这篇 **附录 A.1** 就是为你准备的国产备选路线：**豆包工作**。

## 2. 系统位置：同样是「Agent = 模型 + 执行框架」，只是换上了「飞书办公外壳」

2026 年 8 月，字节跳动完成了旗下 AI 办公产品的统一整合：把飞书、扣子（Coze）与原 TRAE Work 的办公场景能力汇聚到统一品牌 **「豆包工作」** 下（飞书内原有的豆包企业版入口同步升级为豆包工作）。

用你第 0.1 课学过的底层公式一眼看透它：

```
主线路线（DSH / Codex）：本地目录 + 终端/网页工作台 + Python/Git（适合自建工具、完全掌控代码）
                        ↕ 底层完全同源：模型 + 执行框架（拆任务 → 调工具 → 交结果）
国产办公路线（豆包工作）：飞书/豆包中文入口 + 任务拆解 + 飞书文档/多维表格/浏览器协作  ← 【本篇位置】
```

一句话判断你适不适合选它：**如果你想自己攒一套沉淀在 GitHub 上的长期脚本工具，继续用主线 DSH / Codex；如果你的日常核心战场就在飞书生态里、追求「零终端上手 + 团队协作交付」，豆包工作非常顺手。**

## 3. 讲清楚：主线课程概念 ⇄「豆包工作」一一映射表

哪怕你换成了完全图形化的「豆包工作」，前面 32 课练出来的监工心法一点没浪费，全部直接平移：

| 主线课程学过的概念 | 在 DeepSeek Harness 里的样子 | 在「豆包工作」里的对应方式 | 监工怎么守底线 |
|---|---|---|---|
| **工作区与输入素材**（1.5 / 3.1） | 本地独立文件夹 `ai-radar/data/` | 飞书云文档、多维表格、上传的本地表格或指定办公目录 | 绝不把整个部门网盘或高敏薪资表一口气全授权进去 |
| **四要素需求单与先计划**（5.1） | 敲 `/plan` 审完书面计划再点「同意执行」 | 发任务时依然按「目标产出 / 范围 / 验收口径 / 禁忌」写清，先让它列出执行步骤确认再跑 | 不写「帮我整理一下群里的数据」，写清输出到哪张表、保留哪些列 |
| **项目说明书 `AGENTS.md`**（5.2） | 项目根目录 `AGENTS.md` | 沉淀成「豆包工作 / 扣子」里的固定工作流指令、Skill 技能模板或团队提示词规范 | 把高频口径和禁止项固化下来，避免每次口头重说 |
| **定时自动干活**（5.3） | DSH「自动化任务」或 GitHub Actions | 结合飞书多维表格自动化、机器人定时触发或办公智能体定时任务，**天然直接推送到飞书群！** | 依然严防无人值守任务自动给外部客户群乱发未经审核的内容 |
| **安全与费用边界**（3.4 / 7.2） | 本地 `.env` + 消费上限 + 关 Session Log | 走字节/飞书企业版权限管控与豆包专业版/企业版订阅计费 | **先看公司 IT 审批！** 涉及客户身份证、薪资、NDA 合同的红灯数据必须走企业合规审批通道 |

### 豆包工作的 3 个明显优势 vs 2 个天然边界

- **3 个明显优势**：
  1. **国内直连、零终端门槛**：不用装 Node.js，不用配代理，中文界面开箱即用；
  2. **飞书生态无缝打通**：读飞书文档、写多维表格、把日报直接推给飞书群，省去自己折腾 Webhook 的步骤；
  3. **多工具与 GUI 操作能力**：支持任务拆解、跨软件/浏览器操作与 Skill 生态，非编程场景（如做汇报、整理文档、填表）覆盖面很广。
- **2 个天然边界（选前想清楚）**：
  1. **代码透明度与可迁移性不如本地 Git 工程**：黑盒化程度更高，出了细节口径偏差时，没法像本地 Python 那样直接敲 `git diff` 盯死改了哪一行；
  2. **进阶办公与企业级套餐成本**：据 2026 年 8 月公开报道，豆包专业版/企业办公采用梯度订阅收费（高级套餐费用显著高于轻度按量 API），中小团队开通前务必按实际高频场景算账。

**最常见的误解**：以为「用了公司里的飞书 + 豆包工作，就再也不用懂 3.4 课的数据安全红线了」。**不对！** 即便在企业协同平台内，也存在「个人免费账号 vs 公司认证企业版账号」「普通群可见权限 vs 机密文档权限」的巨大差别——切忌用个人账号随手处理公司红灯敏感表，先核实你的账号归属与数据留存政策！

## 4. 现场看：把 `ai-radar` 每日早报翻译成「豆包工作」3 步落地法

假设你不想碰 Python 和终端，只想在公司飞书里每天早上收到一份类似 `ai-radar` 的《每日 AI 情报早报》，照下面 3 步把主线技能平移过去：

1. **第 1 步（定清四要素需求与固定模板）**：
   - 在飞书先建一张空的《每日 AI 情报早报》多维表格（列固定为：`日期`、`标题`、`热度/来源`、`一句话中文摘要`、`原文链接`），相当于你在 3.1 课定好的 `output/` 成品格式；
   - 写清规则：只抓公开信息源（如 Hacker News AI 热点或指定官方博客），输出严格按这 5 列填写。
2. **第 2 步（先小范围试跑 + 监工逐条核验）**：
   - 在豆包工作办公任务模式里下发四要素指令，先让它只试跑「今日 5 条」写入测试表（不要一上来直接发大群！）；
   - 你肉眼核对：链接能不能点开？有没有胡编标题（幻觉）？摘要有没有偏离原文？
3. **第 3 步（验收通过后再接飞书定时推送）**：
   - 确认连续 2–3 天质量稳定后，再配置「工作日早上 8:30 自动触发」并先推给你自己的个人飞书会话，抽查无误后再决定是否推到团队群。

## 5. 你来读：这 3 种职场需求，该选「豆包工作」还是回到主线「DSH + Python」？

停下来想 10 秒，用本篇学到的边界做出判断：

1. **需求 A**：行政/运营同事每天要把飞书群里各门店报上来的文字进度整理进飞书多维表格，再生成一段通知草稿发给主管确认，完全不想学终端。
2. **需求 B**：财务/数据分析岗每周要把 50,000 行含客户真实手机号的本地 CSV 清洗脱敏，严格按四舍五入公式精确算账，并且要求结果 100% 可复现、不能有任何大模型计算幻觉。
3. **需求 C**：你想把一套公开行业数据监控工具长期开源放上 GitHub，方便团队里用 Mac、Windows、DSH、Codex 的人随时克隆复用。

**判断思路**：
1. **需求 A 非常适合「豆包工作」**：核心工作流原生在飞书文档与多维表格里，重文字归纳而非海量精确数值计算，零终端上手最快。
2. **需求 B 坚决回到主线「本地 Python 脚本（DSH / Codex 写代码 + 本地跑）」！** 原因有二：① 50,000 行含真实手机号属于红灯隐私数据，必须走 3.4 课的「本地脚本先脱敏、原表不进云端」；② 精确算账必须交给 100% 确定性的 Python 代码，绝不能靠大模型口算！
3. **需求 C 回到主线「Git + GitHub 标准工程结构」**：跨平台、跨工具、版本留痕与开源协作，依然是本地代码仓 + `AGENTS.md` 最稳。

## 6. 小检查（3 道判断题）

1. 选用「豆包工作」这类零终端图形化办公智能体后，前面课程学的四要素需求写法、先小步验收和数据安全分级就全都用不上了。（对 / 错）
2. 当团队日常协作深度绑定飞书文档与多维表格、且任务以文字归纳和办公流程串联为主时，豆包工作比纯终端工具上手门槛更低。（对 / 错）
3. 面对几万行含真实手机号的敏感业务表做精确财务核算时，应优先采用「本地 Python 脚本先脱敏并在本机运行」的确定性方案，而不是直接把整张原表拖进云端办公对话框让大模型口算。（对 / 错）
