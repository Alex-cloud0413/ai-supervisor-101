## 内容卡 01

- **页眉标签**：01｜壳会变，底下 5 层监工底座 100% 不变
- **正文**：
  - **目录骨架**：`data/`、`scripts/`、`output/`、`config.yaml` 完全不变
  - **项目说明书**：根目录 **`AGENTS.md` 一字不改直接复用**
  - **权限三档**：只读 / 工作区内修改 / 高危全放开，全行业通用
  - **协作心法**：四要素需求 + 先审计划再动手，完全一样
  - **验货回退**：`git diff` 和 `git restore` 不挑任何 AI 工具！

---

## 内容卡 02

- **页眉标签**：02｜DeepSeek Harness ⇄ Codex 一眼对照
- **正文**：
  - 全局说明书：`~/.dsh/AGENTS.md` ⇄ **`~/.codex/AGENTS.md`**
  - 项目说明书：都是项目根目录 **`AGENTS.md`**（上限同样精简控制）
  - 权限切换：DSH 点选三档 ⇄ Codex 敲 **`/permissions`**（选 `workspace-write`）
  - 切换模型：DSH 右下角下拉 ⇄ Codex 敲 **`/model`**

---

## 内容卡 03

- **页眉标签**：03｜最常见误解：换工具不用推倒重做！
- **正文**：
  - 你的 `.venv`、`requirements.txt`、`config.yaml`、Git 历史全属于你自己，**不属于任何一家 AI 厂商**
  - 甚至连 Claude Code 也一样（只需放一行 `CLAUDE.md` 指向 `AGENTS.md`）
  - 被厂商锁死的，只有「永远在网页聊天框复制粘贴」的用法

## 正文配文（小红书发布参考）

很多人不敢花时间系统学 AI 编程工具，总怕「刚学会一个，半年后出个新神器又白学了」。

其实打开 OpenAI Codex 官方文档一对照就彻底安心了：
它同样原生读取你项目里的 **`AGENTS.md`**，同样分三档沙箱权限（`read-only` / `workspace-write` / `danger-full-access`），验收照样靠 **`git diff`** 和 **`git restore`**！

真正保值的从来不是记某个按钮在哪，而是你手里这套标准工程结构和监工思维。下张卡片（正课大结局）帮你把 DSH 和 Codex 的账单、网络和场景一次比清楚！
