## 内容卡 01

- **页眉标签**：01｜`README.md` 给人看，`AGENTS.md` 给 AI 看
- **正文**：
  - 每次新开会话，AI 都会失忆，你忘叮嘱一句它就可能改歪
  - 放一份 **`AGENTS.md`** 在项目根目录，每次开新对话工具**自动读进 AI 脑子**
  - **两层加载**：全局 `~/.dsh/AGENTS.md`（个人通用习惯）+ 项目 `AGENTS.md`（本项目红线）
  - **跨工具通用**：DeepSeek Harness、Codex、Cursor 全认 `AGENTS.md`（Claude Code 认 `CLAUDE.md`）

---

## 内容卡 02

- **页眉标签**：02｜抄作业！一份好用说明书的 5 个板块
- **正文**：
  - **① 目录分工**：哪放原表（只读）、哪放脚本、哪放成品
  - **② 自检命令**：精确贴出验证命令，逼 AI 跑通再交卷
  - **③ 口径约定**：可变参数放 `config.yaml`，过滤规则写死
  - **④ 绝对红线**：不改 `data/` 原文件、不写死 Key、大改先出计划
  - **⑤ 交付习惯**：大改先开分支，改完亮 `git diff --stat`

---

## 内容卡 03

- **页眉标签**：03｜写 `AGENTS.md` 的 3 条黄金守则
- **正文**：
  - **写死不写虚**：写「过滤 `:free` 后缀」，别写「注意数据准确」
  - **宁短勿长**：控制在 **40–80 行（1 屏左右）**，别塞 600 行公司大百科
  - **踩坑迭代**：AI 犯一次低级错，就往里补一行，越用越顺手

---

## 内容卡 04

- **页眉标签**：04｜千万别踩的 2 个红线误区
- **正文**：
  - **误区 1：把真实 API Key 写进 `AGENTS.md`**
    错！`AGENTS.md` 会进 Git 仓库，密钥永远只放本地 `.env`！
  - **误区 2：以为写了 `AGENTS.md` 就不用审批和存档**
    错！它是「员工手册（软约束）」，真正兜底仍靠权限审批 + `.gitignore` + Git 存档！
