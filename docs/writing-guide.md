# 写作规范

> 本规范在作者个人写作风格（技术解释模式）的基础上，补充本课程的专用约定。3 节样课审定后会再更新一次。

## 1. 读者是谁

职场白领和小老板。会用电脑、微信、Excel，没写过代码，没开过终端。他们关心的是"这能帮我少干多少活、会不会出事"，不关心技术本身有多酷。

## 2. 每课的固定结构

### 2.1 图文稿 `lesson.md`

| 部分 | 作用 |
|---|---|
| 开头场景 | 一个真实操作截图或工作场景，说明这课为什么值得看 |
| 系统位置 | 这课的概念在"AI 干活的完整流程"里处于哪一环 |
| 讲清楚 | 新术语当场解释：是什么、在哪、输入输出、一个例子、最常见的误解 |
| 现场看 | 真实操作截图，配说明 |
| 你来读 | 给一段命令 / 代码 / 页面，让学员自己判断 |
| 小检查 | 3 道判断题，答案放在文末 |
| 下一课 | 一句话衔接 |

### 2.2 录播参考脚本 `video-script.md`

- 作者本人边操作边录，脚本只作参考：给出口播要点、操作步骤、屏幕重点，不写成逐字稿。
- 中英混读的术语给出读法，例如 `Harness` 读作"哈尼斯"、`diff` 读作"迪夫"。

### 2.3 速查卡 `card.md`

- 小红书 1 张封面 + 3–6 张内容卡的文案；每张卡推进一个语义点，不重复标题。

## 3. 语言

- 技术解释模式：准确第一，但保留作者的直接判断。
- 直接主动的动宾表达：写"AI 创建了文件"，不写"文件被创建"。
- 界面文字用当前中文界面标签，加「」；命令、文件名、代码用反引号。
- 不说"读者""笔者"；可以直接用"你"，因为这是教程场景。
- 避免模板化对仗（"这不是……而是……"）、空洞升华、每段一句金句。
- 一课只用一个贯穿始终的例子。

## 4. 贯穿全课的虚构场景

**「青禾文具」**：一家 12 人的文具贸易小公司。老板姓周，运营专员小林负责每周汇总销售数据、整理发票、维护客户名单。所有练习数据都以这家公司为背景，数据完全虚构。

## 5. 截图

- 来源：DeepSeek Harness 网页版 `0.2.2-rc.5`，演示模型为 Gemini。
- 文件名：`<课号>-<序号>-<内容>.png`，例如 `0.1-03-trajectory.png`。
- 截图中不得出现 API Key、个人邮箱、真实路径中的用户名。
- 需要作者在本人电脑上补拍的位置，在稿中标注 `[可选补拍：说明]`。

## 6. 事实核查

- 工具功能以官方文档或实际操作为准，并在文末"参考"中给出链接。
- 区分：实际操作结果 / 官方说法 / 作者推断。
