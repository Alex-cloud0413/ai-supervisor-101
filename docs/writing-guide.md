# 写作规范（v1.0，样课定稿版）

> 本规范在作者个人写作风格（`yiming-writing-style` 技术解释模式）的基础上，结合已定稿的 3 节样课（`0.1`、`1.3`、`4.4`）固化课程专用约定。后续模块统一按此执行。

## 1. 读者是谁

职场白领和小老板。会用电脑、微信、Excel，没写过代码，没开过终端。他们关心的是「这能帮我少干多少活、会不会出事」，不关心技术本身有多酷。

## 2. 每课的固定结构

### 2.1 图文稿 `lesson.md`

文首固定两行元信息：
- `> 学习目标：...`（每课只保留一个明确学习目标）
- `> 演示环境：...`（写明工具版本、模型或仓库日期，及 `ai-radar` 公开数据工作区背景）

正文固定 7 节 + 2 节文末附栏：

| 部分 | 作用 |
|---|---|
| `1.` 开头场景 | 一个真实翻车现场、操作截图或老板提问，直接说明这课为什么值得看；不铺垫宏观大道理 |
| `2.` 系统位置 | 用纯文本流程图把本课概念钉进「AI 干活的完整流程」，标出 `【本课位置】` |
| `3.` 讲清楚 | 新术语在首次出现处当场解释：是什么、在哪、输入输出、一个例子、最常见的误解；涉及操作系统差异时并列给出 Mac / Windows 对照 |
| `4.` 现场看 | 真实操作截图或实操记录，按步骤点出监工要看的关键信号 |
| `5.` 你来读 | 给一段真实命令 / 代码 / 页面 / 场景，让学员停下来想 10 秒，再给出参考判断 |
| `6.` 小检查 | 3 道判断题（末尾标 `（对 / 错）`），答案不放当场，统一放在文末 |
| `7.` 下一课 | 一句话自然衔接下一课的课号与标题 |
| 文末附栏 1：`小检查答案` | 逐题给结论（**对** / **错**）+ 一句话原因 |
| 文末附栏 2：`参考与事实边界` | 明确拆分「实际操作结果 / 官方资料（附链接）/ 作者说明或环境差异」 |

### 2.2 录播参考脚本 `video-script.md`

- 作者本人边操作边录，脚本只作参考：按时间段给出 `屏幕画面` 和 `口播要点`，标出关键停顿与破误解节点，不写成逐字稿。
- 顶部写明建议时长（通常 8–12 分钟）。
- 开头固定附 `## 中英术语读法` 表格（术语 | 读法 | 首次出现时的口头解释），例如 `Harness` 读作「哈尼斯」、`diff` 读作「迪夫」。
- 末尾固定附 `## 录制注意事项`（隐私脱敏、环境/随机性应对）。

### 2.3 速查卡 `card.md`

- **当前交付范围**：暂只交付纯文字文案（`card.md`），**不单独出图**；等作者统一通知后再按 `yiming-technical-image-text` 规则批量渲染。
- 固定结构：顶部排版适配备注 → `封面卡（第 1 张）`（主标题 + 副标题/导语）→ 3–6 张内容卡（每张带 `**页眉标签**：01｜...`，推进一个独立语义点，不重复标题）→ `正文配文（小红书发布参考）`（带话题标签，必含 `#给AI当监工`）。

## 3. 语言与表达

- 技术解释模式：准确第一，但保留作者的直接判断。
- 直接主动的动宾表达：写「AI 创建了文件」，不写「文件被创建」。
- 界面文字、引用概念和表格列名用当前中文标签并加「」；命令、路径、文件名、代码、英文参数用反引号 `` ` ``。
- 并列连接词优先用「和」「、」，少用偏书面的「与」（固定专名或标题约定除外）。
- 不说「读者」「笔者」；教程场景可以直接用「你」。
- 避免模板化对仗（「这不是……而是……」「不仅……更……」）、空洞升华、每隔两段制造一句金句。
- 一课只用一个贯穿始终的例子；涉及路径、终端、安装、权限时，Mac 和 Windows 双系统写法并列给出。

## 4. 贯穿全课的实战项目

**`ai-radar`（AI 选型与每日情报雷达）**：不再使用虚构的传统文具公司，直接以「职场白领 / 小团队负责人」的真实视角，带着 AI 从零搭一套自己每天真能用上的工具：

- **上半场（M0–M4 主线）· 模型比价雷达**：基于 [OpenRouter 公开模型目录](https://openrouter.ai/api/v1/models) 真实快照（`practice/data/openrouter-models-2026-11-24.json`，470 个真实 2026 模型，内置 `-1` 动态路由、`0` 免费限流版、`:batch` 离线变体、每 token 美元字符串等天然真实数据坑），辅助团队选型与算账。
- **下半场（M3/M4 接入 → M5/M6 定时与毕业项目）· 每日 AI 情报早报**：接入 [Hacker News 公开搜索接口](https://hn.algolia.com/api/v1/search?tags=front_page)（`practice/data/hn-frontpage-2026-11-24.json`）和 GitHub Releases，结合 `config.yaml`、`AGENTS.md` 与定时任务，每天自动生成《每日 AI 情报与模型动态简报》。

仓库里同步附带静态公开快照与 [fetch_snapshots.py](../practice/scripts/fetch_snapshots.py)，确保国内学员断网或受限时也能 100% 离线复现；严禁在数据或截图中出现任何真实私人信息或未脱敏敏感凭据。

## 5. 截图与实操素材

- 主线演示来源：DeepSeek Harness 网页版 `0.2.2-rc.5`，演示模型为 Gemini（国内学员替代步骤统一用 DeepSeek 官方 API Key）。
- 文件名：`<课号>-<序号>-<内容>.png`，例如 `0.1-03-trajectory.png`、`1.3-01-access-modes.png`。
- 所有截图必须来自真实运行（DSH 网页版、真实终端输出或官方网页），**严禁伪造软件界面**。
- 截图中不得出现 API Key、个人邮箱、真实路径中的个人用户名。
- 需要作者在本人 Mac / Windows 电脑上补拍的桌面端或系统原生弹窗位置，在稿中明确标注 `[可选补拍：说明]`。

## 6. 事实核查与双端归档

- 工具功能、安全边界、配置路径以官方文档或实际操作为准，并在文末「参考与事实边界」给出链接与采集日期。
- 严格区分：实际操作结果 / 官方资料 / 作者说明或推断。
